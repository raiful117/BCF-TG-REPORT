| Input | Telethon call | Scope |
|---|---|---|
| Post link `t.me/chan/123` | `messages.ReportRequest(peer, id=[msg], option=bytes(reason), message)` | single post |
| Username → Channel / Group / User / Bot | `account.ReportPeerRequest(peer, reason, message)` | whole entity |

> [!NOTE]
> `[+] report sent` = Telegram **accepted the request**. Moderation outcome is server-side. Volume without valid reason can restrict the *reporting* account — pace it, use aged sessions, keep reasons honest.

<!-- ═══════════════ TROUBLESHOOTING ═══════════════ -->

<div align="center">

<h2>
  <img src="https://readme-typing-svg.demolab.com?font=JetBrains+Mono&weight=700&size=28&duration=2000&pause=500&color=00E5FF&center=true&vCenter=true&width=700&height=50&lines=%F0%9F%9B%A0%EF%B8%8F+Troubleshooting" />
</h2>

</div>

<details>
<summary><b>ApiIdPublishedFloodError</b></summary>

Leaked `api_id`. Telegram blocks it. Generate your own at [`my.telegram.org`](https://my.telegram.org).
</details>

<details>
<summary><b>ImportError: cannot import name 'ReportRequest' from 'telethon.tl.functions.channels'</b></summary>

`channels.ReportRequest` does not exist in Telethon. Channel reports go through `account.ReportPeerRequest`. Current build is correct.
</details>

<details>
<summary><b>TypeError: ReportRequest.__init__() got an unexpected keyword argument 'reason'</b></summary>

`messages.ReportRequest` takes `peer, id, option, message` — no `reason`. Reason serialized into `option=bytes(reason_obj)`.
</details>

<details>
<summary><b>FloodWaitError</b></summary>

Rate limit. Tool sleeps automatically. Repeated floods → reduce count, add sessions, slow down.
</details>

<details>
<summary><b>Session not authorized</b></summary>

Delete the `.session` file and re-add via Menu → 1.
</details>
